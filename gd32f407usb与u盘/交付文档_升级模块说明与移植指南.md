# GD32F407 U盘/拖拽升级模块 — 交付说明与移植指南

> 版本：v1.0（2026-08-17）
> 适用：GD32F407 系列水质检测设备（裸机 / uCOS-II 双环境）
> 用途：领导汇报用概要 + 后续同事移植参考

---

## 一、项目概述

本模块为 GD32F407 设备提供**两种固件升级方式 + 完整失败保护**：

| 升级方式 | 原理 | 适用场景 |
|---|---|---|
| **U 盘升级**（Host） | 插 U 盘 → 自动读 firmware.bin → 写入升级 | 现场人员操作 |
| **拖拽升级**（Device） | USB 连电脑 → 拖入 firmware.bin → 自动升级 | 产线/调试 |

**核心价值**：升级过程有 **A/B 双槽 + MD5 校验 + 断电重试 + 自动回滚** 四重保护，升级失败可自动恢复旧固件，设备不会变砖。

**关键设计**：整个模块与操作系统、具体芯片引脚**完全解耦**——同一份代码可运行在裸机或 uCOS-II 下，换板子只需改配置文件。

## 二、文件结构

```
f407_upgrade_gd/                  ← APP 工程（升级模块主体）
├── USER/                        ← 入口：main.c / 中断文件 / 工程文件
├── Libraries/                   ← GD32 标准外设库 + USB 栈（第三方）
└── usb_upgrade/                 ← ★ 升级模块本体
    ├── plat/                    ← 平台抽象层（纯接口 + 开关，无硬件代码）
    │   ├── plat_config.h        ← ★ 平台开关（裸机/uCOS、TIM 来源）——移植只改这里
    │   ├── plat_tick.h          ← 时间抽象（延时/时间戳）
    │   ├── plat_flash.h         ← SPI Flash 抽象
    │   ├── plat_log.h           ← 日志抽象
    │   ├── plat_reset.h         ← 复位抽象
    │   ├── plat_timer.h         ← 定时器回调机制
    │   └── plat_button.h        ← 按键抽象
    ├── bsp/                     ← 平台实现层（GD32 具体实现）
    │   ├── board_pin_config.h   ← ★ 引脚配置（Flash/USB/串口/按键/LED/TIM）
    │   ├── partition_table.h    ← ★ 分区表（Flash 布局单一来源）
    │   ├── plat_tick_internal.c / external.c / ucos.c  ← TIM 三后端
    │   ├── plat_flash_w25q128.c / plat_log_uart.c / plat_reset_gd32.c
    │   └── plat_button_gd32.c / plat_timer.c
    ├── src/                     ← 业务核心层（零平台依赖）
    │   ├── upgrade.c            ← 升级状态机 + MD5 校验
    │   ├── flash_service.c      ← Flash 缓存 + 互斥（裸机/uCOS 双分支）
    │   ├── usb_mode.c / usb_task.c / usb_host_task.c  ← 模式与升级流程
    │   └── md5.c / firmware_check.c / upgrade_source.c / fatfs_system.c
    ├── middleware/FatFS/        ← 文件系统（ff.c + 双卷 diskio）
    └── usb_app/                 ← USB 栈应用层（Host/Device 封装）
```

**三层架构一句话**：`src/`（业务，任何平台通用）→ `plat/`（接口，只定义签名）→ `bsp/`（实现，GD32 专用）。

## 三、核心功能清单

### 3.1 升级能力

| 功能 | 说明 |
|---|---|
| U 盘升级（Host） | 插 U 盘自动升级，无需电脑 |
| 拖拽升级（Device） | USB 连电脑拖入 firmware.bin 升级 |
| 自动复位续跑 | 升级完成 → 自动复位 → Bootloader 搬运 → 跳转新固件 |
| 模式切换 | KEY 长按 1.5s 在 DEVICE/HOST 间切换（标志存 Flash） |

### 3.2 可靠性保护（核心卖点）

| 保护 | 原理 |
|---|---|
| **A/B 双槽** | 新固件写 Slot A，旧固件备份 Slot B，损坏可回滚 |
| **MD5 四重校验** | 写 Slot A 后 / 搬运前 / 搬运后 / 回滚前各校验一次 |
| **断电重试** | 中途断电 → 下次启动自动继续（标志区分首次/重试） |
| **自动回滚** | 搬运失败 → 自动从 Slot B 恢复旧固件 |
| **固件上限** | 支持 ≤2MB 固件（当前实际 58KB，余量极大） |

### 3.3 Flash 分区（与 OTA 工程对齐）

```
0x000000  Slot A（升级缓冲区）   2MB    ← 与 OTA 复合使用
0x200000  Slot B（App 备份区）   2MB
0x400000  文件区（FatFS）        3MB
0x700000  升级配置区            64KB（前 32KB OTA / 后 32KB 本模块）
0x710000  加密区 / 保留区 / 字库区（本模块不使用）
```

### 3.4 对外接口（集成只需 2 个函数）

```c
USB_Upgrade_Init();   /* 初始化升级模块（上电调用一次） */
USB_Upgrade_Run();    /* 升级轮询（放入周期任务/主循环，一次推进一点） */
```

## 五、移植指南（给同事的实操手册）

### 5.1 移植框架：三步接入

```
第 1 步：配置（改 3 个文件，见第四章）
第 2 步：初始化（启动流程调一次）
第 3 步：轮询（放入已有周期任务）

目标工程侧的全部改动：
┌─────────────────────────────────────────────┐
│ ① plat_config.h    → PLAT_SELECT / PLAT_TIMER_SOURCE │
│ ② board_pin_config.h → 引脚（Flash/USB/串口/按键/LED/TIM）│
│ ③ partition_table.h  → 分区（与 OTA 对齐时）         │
│ ④ 启动处：USB_Upgrade_Init();                      │
│ ⑤ 周期任务里：USB_Upgrade_Run();                   │
└─────────────────────────────────────────────┘
```

### 5.2 定时器（TIM）接入 —— 三选一

| 情况 | 配置 | 额外动作 |
|---|---|---|
| 独立调试 | `PLAT_TIMER_INTERNAL` | 无（用本工程 TIMER2） |
| **复用目标工程已有定时器**（推荐） | `PLAT_TIMER_EXTERNAL` | 定时器中断里加 1 行 `plat_tick_isr()`（10ms 中断调 10 次） |
| uCOS 环境 | `PLAT_UCOS2`（自动 OSTICK） | 无（用 OS tick） |

### 5.3 uCOS-II 接入 —— 2 个函数扔进已有任务

```c
/* ① 初始化（OSInit 后 / 首个任务内调一次） */
USB_Upgrade_Init();

/* ② 选一个"周期性运行"的已有任务，加一行 */
void Main_Task(void *p_arg)
{
    for (;;) {
        ...目标工程原有业务...
        USB_Upgrade_Run();   /* 升级轮询，一次推进一点 */
        OSTimeDly(...);      /* 原节拍不动 */
    }
}
```

> 无需新建任务、无需分配任务栈。升级期间该任务会短暂停顿（擦除 150ms~2s），
> 本设计按"可接受停业务"场景开发；若业务任务不允许停，需另建低优先级任务。

### 5.3.1 uCOS 移植专项（已修复验证，移植时直接可用）

uCOS 分支（`plat_tick_ucos.c`）已通过严格审查并修复 3 个问题，裸机编译验证 0 Error，**未在 uCOS 真机环境跑过，移植后需实测**：

| # | 已修复项 | 说明 |
|---|---|---|
| 1 | 补 `plat_tick_deinit()` / `plat_tick_isr()` | uCOS 模式 OS tick 归目标工程管，deinit 为空实现（复位流程由目标工程停自己的 tick 源），空桩仅为满足声明一致、保证链接 |
| 2 | `OSTimeTickHook` 改 `__weak` | 避免与目标工程 os_cpu_c.c 的强定义冲突；**若目标工程已有该钩子，需在其内部补一行 `plat_timer_poll()`**，否则升级模块的 timer 回调不驱动 |
| 3 | `plat_delay_ms` 循环分段 | uCOS-II 的 `OSTimeDly` 参数是 INT16U（单次最大 65535 tick），长延时直接传入会被截断，已改为每段 ≤65535 循环延时 |

**uCOS 移植接入要点**：
1. 先把目标工程 uCOS 库加入编译（`os.h` / `includes.h` / `ucos_ii.h` / `os_cpu_c.c`）——本工程不携带 uCOS，需目标工程提供，否则 uCOS 分支无法编译；
2. 确认目标工程 OS 配置：`OS_TICKS_PER_SEC`（决定延时精度）、`OS_MUTEX_EN` / `OS_CPU_HOOKS_EN` / `OS_MAX_EVENTS`；
3. 互斥：`flash_service.c` 的 uCOS 分支（OSMutex）已就绪，DEVICE 模式主循环轮询调用安全（不违反"互斥不进中断"铁律）；
4. 复位：跳转 Bootloader 前目标工程负责停自己的 OS tick（`plat_tick_deinit` 已留空接口，可在其中接入目标工程的停止函数）。

### 5.4 注意事项（按重要程度排序）

| # | 注意事项 | 说明 |
|---|---|---|
| 1 | **分区两边必须一致** | `partition_table.h`（APP）与 Bootloader 工程 `upgrade_config.h` 同步改，否则 Bootloader 从错误地址搬运 |
| 2 | **跳转前必须停 tick** | 复位流程已内置 `plat_tick_deinit()`；EXTERNAL 模式需确认目标工程自己的定时器已停（框架提供 weak 钩子，默认已处理 GD32 标准库） |
| 3 | **FatFS 是单例** | 目标工程已有 FatFS 时**不能带第二份**，需融合：合并 diskio、统一卷号、开 `FF_FS_REENTRANT` + 4 钩子对接 OSMutex |
| 4 | **禁止自动格式化设备卷** | `fatfs_system.c` 的自动格式化逻辑融合时必须移除，防止误格式化目标工程自己的盘 |
| 5 | **互斥不进中断** | uCOS 下 `OSMutexPend` 不能在中断里调用；USB 中断路径若访问文件系统需改"置标志+任务处理" |
| 6 | **烧录顺序** | 分区变更后 Bootloader + APP 必须**同时烧录**，否则旧标志/旧数据错位 |
| 7 | **KEY 模式切换** | 长按 1.5s 切 DEVICE/HOST；恢复模式：按住 KEY 上电强制 DEVICE |
| 8 | **日志分级** | `PLAT_LOG_LEVEL` 量产可改 `PLAT_LOG_ERR` 关掉调试输出 |

### 5.5 验证清单（移植完成后逐项确认）

```
1. 编译 0 Error（裸机/uCOS 各一次）
2. 上电无卡死，LED 心跳正常
3. U 盘升级全流程（枚举 → 写入 Slot A → MD5 → 搬运 → 跳转）
4. 拖拽升级全流程
5. 升级完成复位不卡死（tick 已正确停止）
6. 断电重试（升级中途断电 → 重启继续/回滚）
7. 拔插重试（U 盘重插能再次升级）
```

## 六、一句话总结

**本模块 = 2 个对外函数 + 3 个配置文件**。集成时把 `USB_Upgrade_Init()` 放启动、`USB_Upgrade_Run()` 放周期任务，改好引脚/分区/OS 开关即可；可靠性（双槽回滚 + MD5 + 断电重试）已内置，无需额外开发。
